\chapter*{Three-converter system with three different types of Grid Forming Converters}
\section*{Test case description}
The studied test case is a simple system with three converters and one fully resistive load, as depicted in Fig.~\ref{ThreeConv}.
\begin{figure}[H]
\begin{center}
\includegraphics[width=\textwidth]{ThreeConvISGT}
\end{center}
\caption{Structure of the three-converter system\label{ThreeConv}}
\end{figure}
Each converter has a different control: the 1 000 MW converter is using a matching control, the 500 MW a dVOC control and the 250 MW an improved droop control. The network consists in four RL lines, linking together the different converters.
The general structure of the converters and their control is presented in Fig.~\ref{GFGeneral}. The current and voltage loops are common to the three converters while the external loop is different.
\begin{figure}[htbp]
\begin{center}
\includegraphics[width=\textwidth]{Schema_Structure_Grid_Forming_and_Control_General}
\end{center}
\caption{Structure of the grid forming converter and its control\label{GFGeneral}}
\end{figure}
Three events are simulated:
\begin{itemize}
\item At $t = 0.5s$, the line connecting the bus 1 and the bus 2 is disconnected ($K_1$ is opened).
\item At $t = 1.5s$, a short-circuit is applied at the middle of the line connecting bus 2 and bus 4.
\item At $t = 1.65s$, the short-circuited line connecting bus 2 and bus 4 is disconnected to clear the fault ($K_2$ and $K_3$ are opened).
\end{itemize}

\chapter*{Voltage Angle Step Test on Grid Forming Converters}
\section*{Test case description}
This test case implements a scenario from the I18 technical documentation of the French Grid (DTR Chapter 8, Article 8.3.3). The chose test case is named \texttt{S\_VolAngStep7\_OC4} and applied identically to three Grid-Forming
converter architectures:
\begin{itemize}
\item \texttt{DynGFMVSM} — Virtual Synchronous Machine control with a PLL feeding the
      Control block frequency reference; the Converter's Park frame remains
      slaved to the internal virtual angle produced by the swing equation.
\item \texttt{DynGFMVSMConvPLL} — same as above, with the grid-measured PLL frequency
      (\texttt{omegaPLL}) additionally fed to the converter block for frame alignment. The reason behind this variation is to see how mirroring the grid frequency in the Converter's loop will afect performances.
\item \texttt{DynGFMDroop} — Droop-based architecture, with no PLL in the active control chain.
\end{itemize}

\paragraph{Network and operating point}
The converter is connected to an infinite bus through a static RL line sized for
$SCR_{min} = 2$ (i.e. $x_{grid} = 0.5$~p.u. on the converter's own $S_{Nom}$ base,
see base-conversion note below), with $x_{eff} = 0.27$~p.u.
Operating point OC4: $P = 0.95$ p.u., $Q = 0$~p.u., $U = 1$~p.u.
All system services (voltage control, frequency regulation, LFSM-U/O) are disabled,
according to section 6, so that only the Grid-Forming voltage-source behaviour is
characterized.

\paragraph{Event and simulation}
At $t = 10$s, a phase jump $\Delta\theta_{grid} = 26.47$° is applied to the infinite
bus voltage. Different simulations will be carried out with diverse solveurs and timesteps. Common features include a simulation from 0 to 25 seconds, with an event at $t=10$s. The output variables out interest are the active current $I_p$ measured at the Point of Generating Unit (PGU).

\paragraph{Conformity criteria}
The I18 technical documentation enforces regulation on the active current $I_p$ mainly trough a set of conformity envelopes and a damping at least equal to 40\% for every oscillation in $I_p$ between 0.1 and 20 Hz.

\subsection*{Simulation setup}
Since the test case is trivial, there is no need for a specific \textit{.iidm} file and initialisation parameters are given as parameters and calculated in a separate case with no perturbation.

\section*{Test case b) --- OpenModelica / OMPython with envelope validation}
\subsection*{Simulation setup}
The same three models are compiled and simulated in OpenModelica (OMEdit v1.24.4),
driven by an OMPython script (\emph{path: TODO}) that:
\begin{enumerate}
\item instantiates the model and sets the OC4 operating point via
      \texttt{compute\_operating\_point()} (rigorous two-bus power flow, from
      \texttt{GFM\_enveloppes.ipynb});
\item applies the $6.36°$ angle step at $t_0$;
\item extracts the resulting current trace and computes the fiche I18 conformity
      envelope from the scenario dictionary already defined in the notebook.
\end{enumerate}
